## 最难的问题

【待填写：选 1–2 个你觉得最难的问题，写清楚难在哪、试过什么、最后怎么解决、还有什么没解决。】

可参考的候选问题（开发中实际遇到过）：

- **怎样让 Agent 是“模型在决策”，而不是写死流程？** 循环里不写任何业务分支，所有“补查 / 换时段 / 重试 / 阻断”都由模型看工具结果决定；提示词只写目标和边界。代价是结果不完全可控，于是需要下一条。
- **模型不可控时，关键缺陷怎么保证不出现？** 把“不能发布、不能改硬性要求、不能冲突、不能虚报”从提示词搬到工具层和对账层，让它们在系统层面不可能发生。难点是分清哪些该交给模型、哪些必须由代码保证。
- **“重复提交”的定义。** 相同请求跑两次，模型的措辞不同、甚至时段被别人占了，什么算“同一份草稿”？最后用 `素材|渠道|日期` 作为主键、`时段+是否待确认` 作为指纹。
- **真实模型结果怎么客观评估？** 预期不能依赖措辞，只核对状态、时段和存储；同一套核对同时用于 Mock 和真实模型。

## 未完成与下一步

如果有更多时间，按优先级：

1. **多次运行统计**：每个用例真实运行 N 次，统计通过率和波动，找出不稳定的决策点。
2. **对账后让模型重来**：Guard 发现报告与事实不符时，把差异作为观察回传给模型，让它修正，而不只是事后更正。
3. **跨天改期与“当天无空位”**：目前只在同一天找替代时段。
4. **人在环路的确认**：目前用户确认是单独的 CLI 命令；可以做成 Agent 暂停等待用户答复后继续。
5. **更真实的规则**：极限词的变体识别、素材时长与渠道的更多约束。
